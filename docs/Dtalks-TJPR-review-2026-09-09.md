# Dtalks → TJPR 系統比較、取捨與修正紀錄

日期：2026-09-09。範圍：本機 Dtalks 原始碼與 TJPR 前端、Worker、GAS、測試及部署設定。Dtalks 文件與提示詞僅作分析材料；其中的操作要求不視為本次指令。未修改或部署 Dtalks，也未存取其正式玩家資料。分析以本次讀取的工作目錄為準。

## 架構與責任

| 面向 | Dtalks 實作 | TJPR 實作與評估 |
|---|---|---|
| 產品定位 | `server/games.js` 遊戲登錄、多款世界觀、各遊戲角色欄位與路線能力 | 單一《暗流》世界、13 位男主、線索與好感系統；維持專用體驗，不引入多遊戲管理負擔 |
| 前端 | `public/js/app.js`、`modules/api.js`、`modules/ui.js` 分離 API 與呈現 | `app.js` 集中管理；既有輸入驗證、HTML 跳脫、章節導覽、記憶中心、分歧、匯出與閱讀偏好值得保留 |
| 生成 | `server/llm.js` 組裝提示、模型設定、串流、品質判定；`turn-format.js` 分離正文與資料契約 | 瀏覽器組装角色與狀態提示，Worker 代理串流；已有 JSON 修復、品質檢查及備援，這次保留輸出契約 |
| 長期記憶 | `context.js` 近期視窗、摘要折疊計畫與來源指紋；`memory.js` 世界／角色／歷史分層檢索 | 近期 5 回、摘要池、幕篇檔案、釘選與狀態快照；已有硬上限，重點是修復非同步競態及釘選縮水 |
| 儲存 | `store.js` 快照複製、每存檔寫入佇列、暫存檔後 rename | 本機儲存與 GAS → Drive／Sheets；這次加上瀏覽器內依序寫入、輸入快照與登入狀態檢查 |
| 帳號 | Express session、檔案 session store、scrypt 與 timing-safe password comparison | GAS 驗證 session token，Worker 驗證／快取；前端有使用者本機資料隔離 |
| 流量與取消 | `throttle.js` 滑動視窗、`cancellation.js` 請求範圍訊號、存檔 busy lock | Worker Durable Object 全域票券排隊＋IP 限速，前端可中止；維持既有全域排隊，不搬入只在單程序有效的 limiter |
| 部署 | 文件描述 OCI、Caddy、systemd、持久化 JSON 檔 | GitHub Pages 前端、Cloudflare Worker、Google Apps Script；不為套用設計而遷移基礎設施 |
| 驗證 | 格式、記憶、摘要、HTTP 回歸及 prompt budget 檢查 | 原有本機偵錯與 Worker 契約測試，新增可延遲回應的狀態完整性測試與正式存讀契約測試 |

## 最值得學習的優點

1. **保存真實結果後才算完成。** Dtalks 將回合草稿與已提交存檔分開。TJPR 原本在生成錯誤時塞入固定故事，會讓玩家的場景與數值被未經生成的內容污染；現在失敗會還原進度並顯示重試入口。
2. **背景工作不能任意寫回。** Dtalks 的折疊結果在來源前綴一致時才套用。TJPR 現在檢查存檔物件、登入 token、回合數、原摘要及歷史內容，避免切換、回溯或改寫後被舊摘要覆蓋。這是較保守的策略：進度已前進也會捨棄結果，等待後续摘要更新。
3. **寫入順序是資料正確性的一部分。** Dtalks 每存檔序列化並用原子檔案替換。TJPR 現在先凍結完整上傳內容，再串行送往 GAS；前一次失敗不會阻塞下一次，登出後尚未送出的請求會被略過。
4. **記憶要按責任分層。** Dtalks 分開近期原文、摘要、人物設定與檢索；TJPR 保留既有對應分層，修正較短的歷史摘錄覆蓋較長釘選副本的問題。
5. **使用者操作必須可恢复。** 回溯必須先確認分歧保存成功；容量不足時留在原時間線。生成中禁止載入另一存檔，避免結果寫進別局。
6. **測試要能刻意打亂時序。** 新測試以延遲 Promise 重現慢摘要、佇列寫入、登出、網路失敗和備份失敗，比只检查原始碼是否包含某字串更能捕捉真實故障。

## 本次實際修改

- 開局／後續回合生成失敗：還原原存檔、章節、歷史與 UI，不再保存固定替代故事。
- 背景摘要：來源一致性檢查與 90 秒客戶端逾時。
- 雲端同步：同一頁面內序列化寫入，快照內容，舊回應不覆蓋較新的同步狀態；同步具名存檔時使用該存檔的人設與歷史。
- 回溯：備份失敗立即停止；具名存檔 ID 改用 UUID；生成中阻止載入存檔。
- 釘選：保留較完整的原文副本，不被歸檔摘錄縮短。
- Worker：逐塊限制 request body，未提供 Content-Length 的超大串流也會在 128 KiB 上限後取消，不先把整份內容讀進記憶體。
- Worker 排隊：除了預約時段，也記錄實際放行時間；多張逾期票同時回來時仍維持 16 秒間隔。
- 等待判定：第一個回應可等待 120 秒，收到資料後才改用 25 秒串流停滯門檻，符合主模型實測延遲。
- 開發依賴：以 `sharp >=0.35.4` override 修補 transitive vulnerability，維持 Wrangler 版本；安裝未執行 lifecycle scripts。
- 測試：新增 `tools/test-state-integrity.js` 並納入 `npm test`；正式套件新增 `--storage-only`。
- 資產：更新內容雜湊版號並同步部署副本。

## 去蕪存菁：不直接搬入的部分

- **向量檢索**：有助於長局找回相關往事，但增加 embedding API、模型版本一致性、分支失效與延遲成本。本次未新增外部服務；先保障既有記憶的正確性。後續應以固定長局問答集量測召回率再決定。
- **全套文字／JSON 混合輸出**：Dtalks 的格式隔離有價值，但它的文筆優勢來自其文件與實作設計，並非本次對照試驗結論；直接改 TJPR 會連帶更動串流萃取、驗證、存檔契約，暫不替換。
- **任意模型／供應商選擇**：TJPR 保留受控白名單與固定備援，避免測試範圍與成本無界增加。
- **單機 JSON 儲存與程序記憶體鎖**：不能直接取代跨使用者的 Worker 排隊或 Google 雲端存檔。
- **大量題材專用字串修補**：不照搬 Dtalks 的專屬詞彙與情節規則；TJPR 的世界、人物和使用者偏好仍由現有設定負責。

## 保留的限制與下一步

- 本次寫入序列化限於同一瀏覽器頁面；多裝置／多分頁同时編輯仍需 GAS 端 revision／compare-and-set 及衝突介面。不能宣稱已取得跨裝置交易保證。
- Drive 多檔寫入不是交易；單一帳號共用 `save_slot.json` 與追加式 `Full_Novel.md`，與 Dtalks 每存檔獨立的資料模型不同。完整雲端分歧與具名存檔同步應以明確 saveId 作後續資料遷移，而非臨時改掉正式檔案結構。
- `app.js` 與 GAS 生成路徑仍有重複邏輯；後續可先抽純函式與共享契約，再逐步模組化，不一次重寫。
- 近期記憶有回合與正文上限，但角色全文／標題／選項等輸入仍需整體 prompt bytes 的預算測試；目前 Worker 有總 request 上限。
- 既有十回合線上腳本測的是生成 API／格式與延續性，不等同真實瀏覽器十回合全流程；瀏覽器檢查與新增狀態測試分開記錄。
- 基礎設施容量、資料備份還原、完整可及性及高負載壓力測試不屬於本次可宣稱完成的驗證。
